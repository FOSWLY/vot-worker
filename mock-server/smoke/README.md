# Smoke-тесты VOT Worker

Smoke-runner проверяет единый пользовательский сценарий через три реализации воркера: [Elysia](../../elysia/), [Axum](../../axum/) и [Cloudflare](../../cloudflare/). Запросы отправляются через `@vot.js/node`, а локальный [mock-server](../README.md) заменяет Yandex API.

По умолчанию runner сам запускает mock-server и выбранный воркер, выполняет проверки и останавливает процессы.

## Быстрый старт

Требуется [Bun](https://bun.com) и зависимости `mock-server`:

```bash
cd mock-server
bun install
bun run smoke -- --worker axum
```

Для Axum также нужен Rust/Cargo. После успешного запуска команда завершится
строкой `smoke all scenarios passed` и кодом `0`.

## Требования

| Режим       | Дополнительно требуется                                      |
| ----------- | ------------------------------------------------------------ |
| Elysia      | `bun install` в `elysia/`                                    |
| Axum        | Rust и `cargo` в `PATH`                                      |
| Cloudflare  | Node.js и `npx`; при первом запуске может скачаться Wrangler |
| Все воркеры | все перечисленные зависимости                                |

## Запуск

Команды выполняются из `mock-server/`:

```bash
# Elysia, Axum и Cloudflare последовательно
bun run smoke

# Только одна реализация
bun run smoke -- --worker elysia
bun run smoke -- --worker axum
bun run smoke -- --worker cloudflare
```

Прямой запуск из корня репозитория:

```bash
bun mock-server/smoke/worker-smoke.ts --worker cloudflare
```

### Уже запущенные сервисы

`--no-spawn` отключает запуск и остановку процессов. В этом режиме воркер уже
должен быть настроен на указанный mock upstream:

```bash
bun run smoke -- --worker axum --no-spawn --worker-url http://127.0.0.1:7674 --mock-url http://127.0.0.1:4000
```

В `--no-spawn` можно использовать произвольные адреса и порты. Runner только
отправляет запросы и не меняет конфигурацию внешних сервисов.

## Параметры

Явный CLI-флаг имеет приоритет над соответствующей переменной окружения.

| Флаг / env                     | По умолчанию                                  | Назначение                          |
| ------------------------------ | --------------------------------------------- | ----------------------------------- |
| `--worker`, `SMOKE_WORKER`     | `elysia`, затем `axum`, затем `cloudflare`    | выбрать одну реализацию             |
| `--no-spawn`, `NO_SPAWN=1`     | выключено                                     | использовать уже запущенные сервисы |
| `--worker-url`, `WORKER_URL`   | адрес выбранного воркера на `127.0.0.1`       | URL воркера                         |
| `--mock-url`, `MOCK_URL`       | `http://127.0.0.1:3001`                       | URL mock-server                     |
| `--worker-port`, `WORKER_PORT` | Elysia `5000`, Axum `7674`, Cloudflare `8787` | порт запускаемого воркера           |
| `--mock-port`, `MOCK_PORT`     | `3001`                                        | порт запускаемого mock-server       |
| `SMOKE_TIMEOUT_MS`             | `15000`                                       | ожидание готовности сервисов, мс    |

При запуске всех воркеров нельзя задавать общий `--worker-url` или `--worker-port`: у реализаций разные адреса по умолчанию. Выберите конкретный `--worker` и запустите проверки отдельно.

## Что проверяется

1. `GET /health` и версия воркера.
2. Создание и декодирование сессии.
3. Обычный перевод видео: processing → done.
4. Перевод с загрузкой аудио: waiting → upload → processing → done.
5. Состояния кеша и клонирования.
6. Обработка `fail-audio-js`.
7. Исходные и переведённые субтитры.
8. Перевод стрима и ping активного стрима.
9. Неизвестный маршрут, невалидный payload и запрос без sec-заголовков.

Если сессию создать не удалось, зависимые функциональные сценарии пропускаются, но негативные проверки всё равно выполняются. Любой провал даёт ненулевой код завершения.

## Управление процессами

В обычном режиме runner:

- проверяет, что порты mock-server и воркера свободны;
- запускает mock-server с включённой проверкой sec-заголовков;
- собирает Axum через `cargo build --quiet` перед запуском;
- запускает Cloudflare через `npx --yes wrangler dev --local`;
- останавливает дочерние процессы после тестов и при `SIGINT`/`SIGTERM`.

Для автоматически запущенного Axum loopback добавляется в `NO_PROXY` и
`no_proxy`, чтобы системный proxy не перехватывал запросы к локальному mock.

## Решение проблем

**Порт уже занят.**

Остановите процесс на указанном порту или используйте `--no-spawn` с уже работающими сервисами.

**Axum получает `502` от локального mock.**

При ручном запуске Axum добавьте `127.0.0.1,localhost` в `NO_PROXY`/`no_proxy`. Автоматический smoke-запуск уже делает это сам.

**Cloudflare не запускается.**

Проверьте наличие `node` и `npx`.
Первый запуск Wrangler требует доступа к npm.
После аварийного завершения на Windows может остаться `workerd.exe`; остановите его перед повторным запуском.

**Сервис не успевает запуститься.**

Перед запуском увеличьте `SMOKE_TIMEOUT_MS`, например до `30000`.

## Ограничения

- В spawn-режиме mock-server должен слушать `127.0.0.1:3001`, потому что этот адрес передаётся воркерам как `YANDEX_API_URL`.
- Внешние S3 audio/subtitles proxy-маршруты не проверяются.
- Состояние mock-server хранится только в памяти.
- Это быстрая проверка сквозного пути, а не полный e2e-набор.
